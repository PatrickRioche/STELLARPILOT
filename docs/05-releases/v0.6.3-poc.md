# StellarPilot v0.6.3-poc

Date : 2026-09-07

## Objectif

La v0.6.3 transforme le catalogue embarqué en catalogue stellaire réellement utilisable pour la sélection de cible et le GOTO, tout en conservant un fonctionnement de terrain entièrement hors ligne.

## Catalogue stellaire

- toutes les étoiles du catalogue stellaire embarqué jusqu'à la magnitude visuelle V = 6,0 ;
- ajout des étoiles portant un nom propre IAU/WGSN disponibles dans la source figée de la version ;
- coordonnées équatoriales J2000 ;
- magnitude V ;
- constellation ;
- noms propres et alias ;
- identifiants HIP, HR et HD lorsqu'ils sont disponibles ;
- désignations Bayer et Flamsteed lorsqu'elles sont disponibles ;
- recherche tolérante aux accents et aux variantes de casse, par exemple `Vega` / `Véga` ;
- recherche possible par désignation, par exemple `Alpha Lyr`, `HIP 91262`, `HR ...` ou `HD ...` lorsque l'identifiant existe.

Le catalogue complet est injecté dans le `catalog.sqlite3` persistant. La migration est idempotente et ne remplace jamais le fichier SQLite. Elle ne remplace que les lignes stellaires appartenant à StellarPilot ; les objets OpenNGC et les autres données persistantes sont conservés.

## Fonctionnement hors ligne

Les fichiers astronomiques externes ne sont pas téléchargés par le Raspberry Pi.

`tools/deploy-server.ps1` :

1. fabrique le kit depuis le commit Git courant sur le PC ;
2. télécharge sur le PC les sources astronomiques figées par commit dans `server/catalog_sources/SOURCE_MANIFEST.json` ;
3. les incorpore au kit serveur ;
4. transfère le kit autosuffisant au Raspberry Pi ;
5. préserve `.venv/` et `data/` sur le Pi.

Le Raspberry Pi peut donc créer et utiliser le catalogue v0.6.3 sans accès Internet.

## Sources figées

La version utilise notamment :

- le catalogue d'étoiles de Sky Map pour les étoiles de magnitude visuelle jusqu'à 6 ;
- un extrait du Yale Bright Star Catalogue 5th edition pour les désignations Bayer/Flamsteed et identifiants HR/HD ;
- un inventaire IAU/WGSN des noms propres et une table associée de coordonnées/identifiants.

Les URL exactes, commits et informations de provenance sont enregistrés dans `server/catalog_sources/SOURCE_MANIFEST.json`.

## Recherche et altitude

Le filtre de hauteur reste actif pour la navigation générale du catalogue.

Exemple : avec un filtre à 15°, la liste générale ne montre que les objets à au moins 15°.

En revanche, une recherche explicite ne masque plus une cible existante :

- `Vega` est retrouvée même si elle est actuellement à 6° ;
- l'API indique alors `visible=false` mais conserve l'objet dans les résultats ;
- l'application affiche `Actuellement trop basse` ;
- un objet réellement sous l'horizon est affiché `Sous l'horizon` et son bouton de pointage est désactivé.

Une cible située au-dessus de l'horizon mais sous le filtre choisi reste sélectionnable et pointable après l'avertissement.

## Alignement

La liste des étoiles brillantes utilisée par l'assistant est maintenant alimentée par le même catalogue SQLite unifié. L'ancienne liste interne de 31 étoiles ne reste qu'en secours lorsqu'un environnement de test ne dispose pas des sources complètes.

## Validation automatisée

Les tests serveur vérifient notamment :

- la présence de plusieurs milliers d'étoiles jusqu'à V = 6 ;
- la présence des noms Vega, Arcturus, Sirius, Deneb, Altair et Polaris ;
- la recherche de Vega par `Alpha Lyr` et identifiant HIP ;
- le maintien d'un résultat explicite lorsque l'objet est sous le filtre de hauteur ;
- le maintien du filtre de hauteur en navigation normale.

## Test terrain recommandé

Après déploiement du serveur puis installation de l'APK v0.6.3 :

1. rechercher `Vega` ;
2. rechercher `Véga` ;
3. rechercher `Alpha Lyr` ;
4. rechercher `HIP 91262` ;
5. rechercher `Arcturus`, `Sirius`, `Deneb`, `Altair` et `Polaris` ;
6. vérifier qu'une étoile sous le seuil de hauteur reste trouvable par recherche explicite avec l'avertissement correspondant ;
7. vérifier qu'une étoile sous l'horizon ne peut pas déclencher le GOTO.
