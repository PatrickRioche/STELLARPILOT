# StellarPilot v0.6.4-poc

Date : 2026-09-07

## Objectif

La v0.6.4 consolide la calibration par darks avant l'évolution du stacker. Elle construit une bibliothèque de calibration persistante, décrit précisément le setup utilisé et génère une carte des pixels chauds réutilisable par le futur pipeline de stacking.

Le stacker scientifique n'applique pas encore automatiquement ces produits dans cette version : cette étape sera réalisée après validation terrain des darks v0.6.4.

## Accès direct aux darks

L'assistant Préparation propose désormais **ALLER DIRECTEMENT AUX DARKS** depuis les étapes précédant les darks.

Ce mode calibration :

- ignore l'astrométrie ;
- ignore le Bahtinov ;
- demande uniquement de poser un bouchon opaque ;
- lance directement la série de darks ;
- revient à la préparation lorsque la calibration est terminée.

Il permet de constituer ou renouveler une bibliothèque de darks sans refaire une préparation complète d'observation.

## Vrais darks INDI

Les acquisitions de calibration utilisent explicitement :

`CCD_FRAME_TYPE.FRAME_DARK=On`

Le gain, l'offset, le binning et la zone de capture courants restent ceux du driver INDI. Le chemin normal de capture LIGHT reste inchangé et remet explicitement la caméra en LIGHT lorsqu'il est utilisé.

## Série et Master Dark

Valeurs v0.6.4 :

- 20 darks par défaut ;
- exposition actuelle : 4 s dans l'assistant ;
- contrôle de chaque FITS ;
- contrôle de la géométrie et du motif Bayer ;
- contrôle de cohérence de la série avant construction du Master Dark ;
- Master Dark construit avec `sigma-clipped-mean-v1` ;
- seuil de clipping : 3 sigma ;
- au moins 3 darks valides nécessaires à la création d'un Master Dark.

Le contrôle de cohérence de série compare le niveau médian et le bruit de fond de chaque dark à des références robustes calculées sur la série. Un dark présentant un saut anormal de niveau ou de bruit est marqué rejeté avant la combinaison du Master Dark. Le profil conserve le nombre de poses rejetées et la raison du rejet.

Produits persistants :

- `master_dark.fits` ;
- `profile.json` ;
- `hot_pixels.fits` ;
- `hot_pixels.csv` ;
- `hot_pixels.json` ;
- tous les darks FITS bruts utilisés ou rejetés.

Les fichiers restent sous `server/data/calibration/darks/` et sont donc conservés par le mécanisme normal de mise à jour du Raspberry Pi.

## Profil de compatibilité du Master Dark

Chaque session archive un instantané du matériel et des conditions de calibration :

- caméra INDI ;
- exposition ;
- gain ;
- offset ;
- binning X/Y ;
- dimensions de capture / ROI ;
- profondeur du capteur ;
- motif Bayer lu dans le FITS ;
- température du capteur ;
- tolérance de température prévue : ±2 °C ;
- monture détectée ;
- train optique KStars/Ekos ;
- tube ;
- type optique ;
- diamètre lorsque la donnée KStars est valide ;
- focale ;
- rapport F/D ;
- facteur de réducteur ;
- focale et F/D effectifs.

L'objectif est qu'un futur stack ne puisse pas appliquer silencieusement un Master Dark provenant d'une configuration caméra incompatible.

## Pixels chauds

Le Master Dark sert également à détecter les pixels chauds persistants.

Pour une caméra couleur Bayer, la détection est effectuée séparément sur les quatre parités de la matrice Bayer afin de ne pas mélanger les canaux R/G/B.

Produits :

- masque FITS binaire ;
- liste CSV des coordonnées `x, y`, valeur et canal Bayer ;
- résumé JSON avec les seuils et le nombre de pixels détectés.

Le seuil initial est volontairement robuste et sera calibré sur les captures terrain de l'Uranus-C.

## KStars / Ekos et INDI

INDI reste la source de vérité pour le matériel réellement connecté et les paramètres courants de la caméra.

KStars/Ekos complète ces informations lorsque le driver INDI ne publie pas le tube optique. StellarPilot lit la base locale :

`~/.local/share/kstars/userdb.sqlite`

Un nouvel endpoint est disponible :

`GET /setup/status`

Il expose notamment le train optique correspondant à la monture et à la caméra INDI réellement détectées.

Si le train Ekos contient encore une valeur d'exemple telle que `Sample Primary 700@F/5.8`, StellarPilot signale le setup comme **à vérifier** au lieu de présenter cette valeur comme une configuration fiable.

Pour le setup terrain actuel, KStars doit être configuré avec le vrai train d'imagerie, par exemple :

- tube : ASKAR 71F ;
- type : Réfracteur ;
- diamètre : 71 mm ;
- focale : 490 mm ;
- F/D : environ 6,90 ;
- monture : LX200 OnStep ;
- caméra : PlayerOne CCD Uranus-C.

## Connexion et Statut Android

La page Connexion affiche maintenant :

- le setup optique détecté ;
- la focale et le F/D lorsqu'ils sont disponibles ;
- l'état de la base KStars ;
- l'état du processus KStars ;
- le nom du train Ekos.

La page Statut ajoute une carte détaillée **Setup optique · KStars / Ekos** avec :

- train optique ;
- tube et type ;
- diamètre ;
- focale native ;
- F/D natif ;
- réducteur ;
- focale effective ;
- F/D effectif ;
- caméra et monture du train ;
- diagnostic de cohérence INDI / KStars.

L'écran Darks affiche également le profil archivé et, à la fin, le Master Dark et le nombre de pixels chauds détectés.

## Validation terrain du 7 septembre 2026

La chaîne serveur v0.6.4 a été validée avec le matériel réel :

- PlayerOne CCD Uranus-C ;
- ASKAR 71F, 71 mm / 490 mm / f/6,90 ;
- train KStars `Imageur` ;
- LX200 OnStep ;
- RAW16 3856 × 2180 ;
- Bayer RGGB ;
- gain 305 ;
- offset 0 ;
- binning 1 × 1 ;
- 20 darks de 4 s ;
- 20/20 darks capturés et initialement valides ;
- température capteur autour de 29,7 °C ;
- Master Dark créé avec succès ;
- carte de pixels chauds créée avec succès.

Cette série terrain a également révélé une pose présentant un niveau médian et un bruit de fond environ deux fois supérieurs au reste de la série. Ce cas a motivé l'ajout du contrôle de cohérence de série décrit plus haut afin que ce type de pose soit désormais rejeté avant le Master Dark.
